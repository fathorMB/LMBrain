# 1. 5.0 Scope — Core vs Optional Capabilities

Date: 2026-08-21
Status: Accepted

## Context

The 4.x line introduced multiple governance capabilities to LMBrain: operator-invited dreaming, kit feedback lifecycle, effort tiers (`luna/terra/sol`), spec tag vocabulary, declarative branching strategy, harness manifests, and verification gate orchestration. While each feature addresses valid use cases, presenting them monolithically diluted the core product identity, bloated `CONTRACT.md` and `AGENT.md`, and increased cognitive load for autonomous agents and operators.

For Milestone 5.0.0, we establish an explicit division between **Core**, **Optional Capability Modules**, and **Retired Capabilities**.

## Decision

### 1. Core (Mandatory Engine & Baseline Governance)

These capabilities form the minimal, non-negotiable core of LMBrain:

| Capability | Scope | Rationale |
|---|---|---|
| **Spec Lifecycle** | `backlog` → `ready` → `working` → `review` → `done` (`discarded`, `parked`) | Core unit of governed work. |
| **Review Lifecycle** | `pending` → `accepted` / `changes_requested` / `blocked` / `superseded` / `remediation` | Independent verification gate for specs. |
| **ADR Lifecycle** | `proposed` → `accepted` / `rejected` / `superseded` | Architectural decision records. |
| **Agent & Proposal Lifecycle** | `draft` → `active` / `inactive` | Governed persona configurations. |
| **Handoff Lifecycle** | `draft` → `ready` → `consumed` / `superseded` / `archive` | Cross-session communication. |
| **Single Workspace Index** | `scan_workspace()` | Deterministic single-pass workspace discovery. |
| **Atomic Persistence & Lock Hierarchy** | Safe file writes, workspace mutation lock | Eliminates TOCTOU and corruption on concurrent updates. |
| **MCP Registry & Typed Dispatch** | stdio tool table | Unified dispatch, schema generation, and UI catalog export. |
| **Operations View** | Dedicated operator gate triage | Centralized workspace-wide operator evidence attestation. |

### 2. Optional Capability Modules

Optional modules extend core governance when configured or present in the workspace. Their documentation is layered into separate files under `contract/<module>.md`:

| Module | Artifacts / Verbs | Status in 5.0 | Rationale |
|---|---|---|---|
| **Verification Gates** | `manifest.toml`, `spec_verify`, `spec_set_verification_gates` | Optional Module (`contract/verification.md`) | Structured verification for high-assurance repositories. |
| **Harness Config** | `harness.toml`, `harness_*` | Optional Module (`contract/harness.md`) | Test harness and test environment declarations. |
| **Technical Debt** | `DEBT-*.md`, `debt_*` | Optional Module (`contract/debts.md`) | Explicit tracking and resolution of governed debt. |
| **Dependencies & Parking** | `spec_dependencies_set`, `spec_park` | Optional Module (`contract/dependencies.md`) | DAG scheduling and unblocking protocol. |
| **Effort & Tags** | `spec_set_effort`, `spec_set_tags` | Optional Module (`contract/effort-tags.md`) | Agent sizing, tier heuristics, and tag taxonomy. |
| **Kit Feedback** | `FEEDBACK-*.md`, `lmbrain_feedback_*` | Optional Module (`contract/feedback.md`) | Upstream governance feedback channel. |
| **Dreaming** | `DREAM-*.md`, `dream_capture` | Optional Module (`contract/dreams.md`) | Operator-invited ideation with language-neutral trigger. |
| **Branching Strategy** | `BRANCHING.json`, `branching_strategy_*` | Optional Module (`contract/branching.md`) | Declarative branching policy. |

### 3. Retired & Cleaned Items

| Capability / Pattern | Action | Rationale |
|---|---|---|
| **Task References (`TASK-*`)** | Retired / Removed | Tasks were retired in 2.0.0; remaining template and doc residues are purged. |
| **String-typed Status Comparisons** | Replaced with `Lifecycle` trait & enums | Eliminates 6 parallel match tables and brittle string lookups. |
| **Hand-rolled YAML Reader** | Replaced with conforming YAML parser | Eliminates parser edge-case corruption while keeping surgical line-preserving writer. |
| **Monolithic `CONTRACT.md` / `AGENT.md`** | Split into Core ($\le 8$ KB) + Modules | Reduces required agent context load to $<25$ KB. |
| **`OperatorVerificationPanel` inside SpecDetail** | Replaced by Operations page | Moves mutating operator actions out of read-only spec consultation view. |
| **Hand-maintained `types/index.ts`** | Replaced by Rust-generated TypeScript types | Enforces schema parity between Rust models and frontend. |

## Migration Impact

- Existing 4.x workspaces remain structurally compatible.
- Client repositories upgrading to 5.0 will transition `CONTRACT.md` / `AGENT.md` to the layered modular layout via the new tool-driven `kit_migrate` flow.
- No existing valid governed artifacts are invalidated.
